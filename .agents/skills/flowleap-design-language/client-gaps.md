# Client gaps

The IPMS screens use the harness client theme and `ui-primitives` as they are ([tokens.md](tokens.md)): no new colour, font, radius, motion or elevation token. Each numbered item below is one follow-up change that the IPMS screens need. Until an item lands, an IPMS screen that needs it cannot pass the [review checklist](review-checklist.md).

1. **Records UI moves into the client.** Today the Records pages are flowleap-os server pages in an iframe (`packages/client/ui-flowleap-records`) with copied tokens; they get only `?theme`, not the user's font list or the macOS menu fill, and have no `ui-primitives`, shortcut registry or `MenuSurface`. Replace them with client React views in an IPMS feature package that read and write through the Records API of flowleap-os. The os service keeps the data, the state machines and the API; its server-rendered pages and the iframe wrapper are removed when the views land.
2. **Two `ui-primitives` extensions.** A visual difference goes into a `ui-primitives` prop ([docs/web-styling.md](../../../docs/web-styling.md#component-rules)), because the records, work and board views are separate packages. `StateDot` gets a `shape` prop for the six shapes of [status-map.md](status-map.md) (today it draws colour only). `Tag` gets the same `shape` prop for the status pill (today it is a status capsule with no shape). The IPMS status wrapper takes the atlas word as a required prop, so an icon cannot render without its word; the words of [status-map.md](status-map.md) go into the English and German dictionaries. The six glyphs need designer approval ([dsh-client-ui-ux](../dsh-client-ui-ux/SKILL.md#reuse-before-adding)).
3. **Nine new parts**, built from existing tokens and placed in the IPMS feature package, not in `ui-theme`: the keycap (a boxed key label read from the registry catalog, item 4); the list row with its sticky group header, skeleton row and selection checkbox; the queue split view; the decision bar docked at the bottom of a scrolling content column, with its part rows, the reason step for negative acts and the overflow menu at 390 px; the properties panel; the evidence quote with its page, the hover excerpt and the missing-evidence state; the Activity timeline; the board card; the avatar with the name on hover, and the avatar stack. The row context menu is a `ui-context-menu` contribution, not a new part; the filter chips are `Pill`.
4. **Command menu and keys.** Extend the app's `session.search` command to an item-scoped ⌘K on `MenuSurface` (one ⌘K for the app), reusing the popup list of `ui-commands`. Register each act of [keys.md](keys.md) as a registry command with its desktop and Web defaults under the registry rules: a Web default without Alt is Mod+Alt, and Record the decision is Mod+Shift+Enter because the composer's fixed Mod+Enter holds ⌘↵. Add a view-scoped single-key layer, as Linear has: single keys (/, 1, 2, M, Space, C, O, R, E, F, X, J, K) and `↵` work only when an IPMS view has focus and focus is not in a text field, an editable element or a menu. Each single key is a rebindable registry command. `↵` (Open the row) is a fixed key of the layer with no rebinding, registered with `registerFixed()`, because the composer's fixed plain Enter holds it, as its fixed Mod+Enter holds ⌘↵. The layer also adds rebindable sequences for `G M` and `G I` (the registry has overlapping two-key chords, and `registerFixed()` sequences cannot be rebound). Buttons and menu items show the current binding with the keycap of item 3; on a coarse pointer no key shows. Context-menu actions set `commandId` so they show the same keys.
5. **Light-theme contrast (a `ui-theme` issue).** Measured in [contrast.md](contrast.md): the light state colours are below 3:1 on white (warn 2.15, success 2.28), so an icon cannot carry a state without its word; `StateDot` has the same gap app-wide. Open a `ui-theme` issue for darker light warn and success roles (flowleap-os already draws about 5.9:1 and 5.6:1). Until then the word is structural (item 2), the idle icon uses `--dsw-alias-label-tertiary` (3.71:1) instead of `--dsw-alias-state-idle-primary` (1.48:1), and no IPMS text uses `--dsw-alias-label-tertiary`, so `ShortcutKeys` (unboxed 12 px text in that colour) is not used as it is.
6. **People service.** A presence and people service from Entra ID with display names and the wall check before any person shows (FlowLeap issue #227).
7. **Checks in CI.** Run `scripts/contrast.mjs` against `ui-theme`, `scripts/check-css.mjs` against the IPMS feature CSS and `scripts/check-copy.mjs` against its `locales.ts` in CI, so that a theme change that fails R10, a value outside the client tokens, or a missing language fails the build.
