# Client gaps

The IPMS screens use the harness client theme and `ui-primitives` as they are ([tokens.md](tokens.md)): no new colour, font, radius, motion or elevation token. Each numbered item below is one follow-up change that the IPMS screens need. Until an item lands, an IPMS screen that needs it cannot pass the [review checklist](review-checklist.md).

1. **The five new components.** The client has none of these, so they are the only client additions, each built from existing tokens and placed with the IPMS feature, not in `ui-theme`: the status icon with its word (the six shapes, and the words of [status-map.md](status-map.md) in the English and German locale dictionaries; a new glyph set needs designer approval, [dsh-client-ui-ux](../dsh-client-ui-ux/SKILL.md#reuse-before-adding)); the list row with its tinted group header and skeleton row; the decision bar docked at the bottom of a scrolling content column, with its part rows and the reason step for negative acts; the properties panel; the evidence quote with its page, the hover excerpt and the missing-evidence state.
2. **Light-theme contrast.** Measured in [contrast.md](contrast.md): `--dsw-alias-label-tertiary` is 3.71:1 on white, below 4.5:1 for text, so the IPMS screens use it for icons only. The state colours are below 3:1 on white (warn 2.15, success 2.28, idle 1.48); the IPMS screens always put the word beside the icon, so the icon carries no meaning alone. A screen that needs an icon without its word needs darker state roles in `ui-theme` first, which is a founder decision.
3. **Command menu and keys.** An app-wide, item-scoped `⌘K` on `MenuSurface`; today `ui-commands` has only the `/` menu inside the chat composer, so reuse its popup list and add the app-wide trigger and the item chip. Register each act of [keys.md](keys.md) as a command in the shortcut registry (`packages/client/shortcuts`) with its `web:macos` and `web:windows` defaults, and render a button's key with `ShortcutKeys` from the registry's catalog, so that a rebinding in `ui-shortcuts` shows everywhere. The registry has two-key chords with overlapping presses but no sequences, so `G` then `M` needs a sequence binding or a fixed sequence through `registerFixed()`.
4. **People service.** A presence and people service from Entra ID with display names and the wall check before any person shows (FlowLeap issue #227).
5. **Checks in CI.** Run `scripts/contrast.mjs` against `ui-theme` and `scripts/check-css.mjs` against the IPMS feature CSS in CI, so that a theme change that fails R10 or a value outside the client tokens fails the build.
