# FlowLeap firm OS: version 1 scope

Status: agreed by the founder on 2026-10-28. Check every new idea against this page. An idea that is not in "v1 supports" goes to "Later" with a ticket, and the work in progress continues.

## The shape of the OS

- **The harness is where the work happens:** chats, agents (the Patent Agent and the firm's own agents), tools, routines. Chats are durable and run on the server, so work continues when the attorney leaves the page.
- **The dashboard is where the attorney sees the work:** the first screen after sign-in, with panels for what needs review, what is coming up, agent activity and budget. Each OS app adds its own panel through a widget slot. Every item opens the work in the harness.
- **The knowledge is where the firm remembers:** cases and their patent data, firm notes with links, and a graph view over both.

## v1 supports

- One firm server: Ubuntu LTS with root access, in any cloud or in the office. The firm chooses the provider and the region.
- Sign-in with Microsoft 365 / Entra ID, with a local admin account as the fallback.
- One runtime for each attorney, with a personal virtual key, a monthly budget and the firm's allowed models, through the model gateway.
- The firm's own model keys (BYOK); the firm chooses the providers.
- Backups to an SFTP or S3 target that the firm owns.
- Off-site access and the demo address through Tailscale.
- Updates from `registry.flowleap.co` with the firm's update key.
- The patent tools (EPO, USPTO, OCR and the FlowLeap tools).
- Agents that an attorney creates from instructions, files and connectors ("Only me").
- Routines (register watch) with a new chat for each run and "Needs review".
- The dashboard as the first screen.
- A disk guard on the firm server.
- A firm skills library: one firm folder of skills, read-only in every runtime, ahead of the FlowLeap pack (#71).
- The office action board: the first work page, the result view of the office action analysis (#81, #46).
